Необходимо реализовать решение - DNS сервис, который принимает запросы по обычному UDP/53 протоколу, в зависимости от настроенных правил дальше отправляет запрос на вышестоящий DNS сервер (по такому же протоколу или DOH/DOT).

Правила настраиваются - по умолчанию на DNS-серера группы A по протоколу UDP/53 (условно), если к примеру есть правило, что все домены из зоны *.ru отправлять на DNS-сервера группы B по протоколу DOH (условно).

Если вышестоящий сервер вернул ответ с записью, у которой слишком маленький TTL, то мы модифицируем ответ и устанавливаем минимально сконфигурированный TTL в ответе и отдаём ответ запросившему клиенту. Также необходим внутренний кэш, чтобы реже ходить в апстримы.

Технические требования:
- Сервис должен запускаться в контейнере с архитекторой ARM64 для роутера Mikrotik (RouterOS v7.23+).
- Должна быть статистика по top-100 самым запрашиваемым доменам с пиковыми запросами в минуту (RPM) с момента пережапуска сервиса.
- При перезапуске сервиса сбрасывается локальный кэш и статистика.
- должен быть веб UI интерфейс для просмотра статистики и конфигурирования правил вручную. Но также должна быть возмодность задать конфигурацию через файл конфигурации сервиса.
- Если будем писать своё решение, то будем использовать Go версии 1.26+.
- Должен быть внутренний in-memory кэш DNS ответов
- Должна быть возможность модифицировать TTL ответов на MIN-TTL значение из конфига, если апстрим вернул маленький TTL.
- Должна быть возможность сконфигурировать разные группы апстримов, которые позволяют создать несколько серверов в группе и протокол обращения к ним (UDP,DOH,DOT).
- ДОЛЖНА быть возможность для группы апстрим серверов задать не только primary сервера, но и fallback сервера, если основные недоступны.
